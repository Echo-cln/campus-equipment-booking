# 物尽其用

“物尽其用”是一个校园共享设备预约与使用登记前端。项目使用原生 HTML、CSS 和 JavaScript，连接课程提供的模拟服务端读取设备和登记数据。

## 功能

- 设备一览支持名称或编号搜索、分页和设备历史记录查看。
- 选择设备后，可按月份、周或日查看登记日期；日历支持箭头翻月，也支持直接选择年份和月份。年份范围为 2000—2100，可在 `config.js` 调整。
- 可查看某日已登记和空闲设备，并提交一件设备最多五个日期的预约；预约冲突以模拟服务端响应为准。
- 设备详情会展示服务端返回的类别、说明、累计次数、位置、型号、开放时段和设备状态；缺少字段会标明“服务端未提供”。
- 服务端未返回预约冲突后，页面会显示设备和日期的提交结果，并在当前浏览器保存最近的提交请求；日历会标记本机提交日期。
- 使用登记表区分日期、时段、预计时长、登记人、设备状态和沟通入口；接口未提供的信息不会用默认值冒充。
- 管理员工作台保留设备目录中的累计 `UseCount` 统计，并可切换“本月”“近 30 天”或自定义日期区间。区间统计根据每台设备的 `UseDate` 登记记录计算。
- 页面包含设备一览、使用说明和公告区块，导航会滚动到对应内容。
- 页面登录入口提供课程演示身份，用于展示使用者和管理员两种界面。
- 成功读取的服务端响应会缓存在浏览器。服务端不可达时可查看已有缓存，但页面进入只读状态，不提交预约。
- 预约单补充预约时段、用途和协调意愿；提交前会检查本机演示预约的时段冲突，并给出空档时段和替代设备建议。
- “预约与设备服务”提供个人预约中心，可查看待确认、已确认、取消申请和完成状态；支持取消申请、管理员演示确认、时段协调请求以及设备交接检查。
- 协调请求需要预约所有者主动开放；接收者可同意或婉拒。同意后仅更新本机演示时段，并保留原始服务端日期供核对。
- 设备报修流程支持描述故障、管理员接手、解决、暂停预约和恢复预约。交接备注包含异常关键词时会自动生成待处理问题。
- 支持设备维护日期登记；维护日会阻止本机演示预约，并出现在维护日历。候补用户可登记设备和日期，预约结束或本机取消后看到空档待确认提醒。
- 管理员可以发布设备维护、设备故障、使用提醒和项目更新公告；用户与管理员均可查看公告。
- 管理员服务概览汇总进行中预约、待处理问题、维护安排和预约时长。
- 登录页新增“使用者体验 / 管理员体验”完整演示入口；无需启动课程服务端即可浏览示例设备、预约冲突、报修、维护、公告及统计数据，两种身份共用同一份浏览器演示记录。
- 完整演示预置了可验证的时段冲突、空档建议、可协调预约、待处理报修、维护日和候补记录，便于现场连续演示预约与管理闭环。

新增的预约状态、时段、用途、候补、协调消息、报修、维护安排、公告和服务概览均保存在当前浏览器的 `localStorage` 中，属于课程演示流程，不会同步到其他电脑或课程模拟服务端。页面会对这些信息标注“本机演示数据”。

完整演示入口不需要启动课程服务端。它使用 `demo-service.js` 提供的本地设备目录和预约查询适配器；服务台的预约、候补、协调、报修、维护、公告和交接记录由 `workflow.js` 保存在当前浏览器。它们只用于演示，不会写入课程服务端，也不会跨设备同步。进入管理员或使用者演示时会自动补齐缺少的示例记录，不覆盖已有记录。

重复演示前如需还原初始样例，可在浏览器开发者工具 Console 执行以下命令后刷新：

```js
[
  "wu-jin-qi-yong:workflow:v1",
  "wu-jin-qi-yong:my-reservations",
  "wu-jin-qi-yong:complete-demo-seeded:v1",
  "wu-jin-qi-yong:demo-session"
].forEach((key) => localStorage.removeItem(key));
```

这只会清除当前浏览器的本机演示记录；不会撤销已经提交到课程服务端的预约日期。

## 本地运行

### 1. 启动课程模拟服务端

在 Windows 上解压课程提供的服务端文件，按课程说明运行 `模拟服务端.exe`。默认地址为 `http://127.0.0.1:12345`。保持服务端窗口开启，并按课程要求将 `Device.txt`、`Record.txt` 放在服务端程序指定的位置。

可以在浏览器访问以下地址检查服务端是否响应：

```text
http://127.0.0.1:12345/getDevices?page=1&pageSize=5
```

如果这个地址无法打开，先检查服务端程序和端口；如果地址能打开而页面仍显示离线，通常需要检查服务端是否允许网页来源的跨域请求。

### 2. 启动网页

在 Windows 终端进入项目文件夹后，运行 Python 自带的静态文件服务器：

```powershell
cd E:\Programs\campus-equipment-booking
py -m http.server 5500
```

保持终端窗口开启，在浏览器访问：

```text
http://127.0.0.1:5500
```

也可以使用其他静态 HTTP 服务器。直接双击 `index.html` 在部分浏览器中会受到本地文件跨域限制；使用本地 HTTP 地址更便于排查问题。

### 3. 设置服务端地址

项目默认连接 `http://127.0.0.1:12345`。如课程模拟服务端运行在其他地址，编辑 `config.js`：

```js
window.SITE_CONFIG = Object.freeze({
  apiBaseUrl: "http://127.0.0.1:12345",
  requestTimeoutMs: 8000,
  pageSize: 5,
  calendarMinYear: 2000,
  calendarMaxYear: 2100
});
```

`apiBaseUrl` 留空时，接口适配器会使用默认地址 `http://127.0.0.1:12345`。

## 演示账号与能力边界

| 身份 | 账号 | 密码 |
| --- | --- | --- |
| 使用者 | `student` | `demo123` |
| 管理员 | `admin` | `demo123` |

这两个账号仅由前端校验，用来演示不同页面入口；浏览器本地保存的演示会话不构成身份认证。课程模拟服务端没有登录、用户身份或角色权限接口，因此管理员入口并非安全边界，不能用于真实账号、真实权限或敏感数据。课程服务端预约记录无法按用户区分；“我的预约”中的用户筛选只作用于本机演示数据。

课程模拟服务端只提供设备目录、按设备/日期查询登记和按日期提交预约等接口，没有预约用途字段、时段、账号归属、撤销预约、审批流程、设备报修与维护写操作、公告写入或站内消息接口。新增服务工作台使用独立的本机演示数据实现上述完整操作流程，不伪称这些状态已经写入服务端。真实部署需要后端新增预约时段与所有者字段、取消/审批接口、报修维护接口、公告管理接口以及带身份和授权的消息接口。

若只想体验网页交互，直接在登录页点击“使用者体验”或“管理员体验”。若要核对课程提供的 WCF 模拟接口，则使用账号密码登录，该入口仍连接 `config.js` 配置的课程服务端。页眉状态会明确显示当前使用的是“完整体验数据”还是“服务端在线/离线数据”。从完整体验切换到服务端登录时，页面会先清除示例设备缓存，再重新读取服务端目录。

### 服务器已启动但页面仍未连接

1. 确认当前页眉不是“完整体验数据”。完整体验模式只读本机样例，不会访问服务端；点击“退出”，再用 `student / demo123` 或 `admin / demo123` 账号密码登录。
2. 在同一台电脑的浏览器打开 `http://127.0.0.1:12345/getDevices?page=1&pageSize=5`。如果无法显示设备 JSON，检查服务端程序是否监听 12345 端口。
3. 如果接口地址能显示 JSON，但网页仍显示离线，通常是服务端的跨域（CORS）设置阻止了页面 JavaScript 请求。浏览器开发者工具 Console / Network 中会出现 CORS 报错；服务端需要允许网页来源发起跨域请求。
4. 检查 `config.js` 的 `apiBaseUrl` 是否与服务端实际地址一致。页面地址和服务端地址不同端口时属于跨源请求，因此即使两个地址分别能打开，也仍需服务端允许 CORS。

日历会标记当前浏览器提交过的日期；“我的预约”集中显示演示用预约流程状态。预约日期仍提交课程服务端，但时段协商、取消处理、管理员确认、归还检查及其状态仅更新本地演示记录。需要取消课程服务端预约时，必须另行联系课程服务端管理员。两名演示账号可在同一浏览器的数据中查看被授权的协调请求；这不是跨设备聊天，也不具有真实账号安全性。

## 页面统计口径

- **累计**：直接读取设备目录的 `UseCount`，保持课程服务端的累计使用口径。
- **本月、近 30 天、自定义区间**：对已选择的设备逐台读取日期记录，并按 `UseDate` 落在所选区间内的记录数汇总。区间统计是预约/使用登记记录数，不代表服务端确认已完成的实际使用；课程接口没有完成状态字段。
- 选择设备支持跨页保留。可选择当前页、全部设备或清空选择。
- “暂无登记”只表示当前接口没有该日的预约记录，不等于设备故障检查合格，也不保证全天可借。

## 接口映射

| 页面功能 | 课程服务接口 | 前端处理 |
| --- | --- | --- |
| 设备目录与累计统计 | `GET /getDevices?page=1&pageSize=10000` | 读取 `No`、`Name`、`UseCount`；前端搜索、分页及累计统计 |
| 设备编号 | `GET /getDeviceNo` | 兼容服务端返回的 XML 字符串数组 |
| 日历与登记历史 | `GET /getRecordByNo?no=...&start=...&end=...` | 将 `UseDate` 转为日期；区间统计按记录日期过滤 |
| 当日已登记 | `GET /getRecordByDate?date=...&page=1&pageSize=10000` | 记录关联设备目录后分页显示 |
| 当日空闲设备 | 当日记录 + `/getDeviceNo` | 以设备编号集合扣除已有登记设备 |
| 提交预约 | `GET /regDevice?No=...&UseDates=日期,日期` | 显示服务端返回的冲突日期；不提交接口不支持的用途字段 |

日期范围统计在浏览器中对每台所选设备请求 `/getRecordByNo`，并依据 `UseDate` 计算，不会修改服务端记录。日期字段可能使用 .NET `/Date(milliseconds)/` 格式，适配器会转换后用于日历与统计。

## 主要文件

- `index.html`：登录入口、设备工作台、日历、管理员统计、使用说明和公告结构。
- `styles.css`：页面视觉样式与响应式布局。
- `app.js`：页面状态、渲染、日历与统计交互、前端演示身份。
- `workflow.js`：浏览器本地预约协作、候补、报修、维护、公告、协调和交接演示流程。
- `demo-service.js`：完整本地体验数据适配器；仅在登录页选择完整演示时替代课程服务端。
- `api.js`：课程模拟服务端接口适配、日期格式转换和只读缓存。
- `config.js`：服务端地址、请求超时、列表页大小和日历年份范围。
- `assets/favicon.svg`：本地图标。

## 手动核对清单

1. 启动模拟服务端和网页，确认设备列表可加载，选择设备后日历与当日记录可显示。
2. 使用 `student / demo123` 登录，确认使用者工作台正常；退出后使用 `admin / demo123` 登录，确认管理员统计入口可用。
3. 在管理员页选择设备，依次核对累计、本月、近 30 天和自定义区间；检查统计卡片、图表标题和统计口径说明同步更新。
4. 在日历中用年月选择器跳转，并用箭头前后翻月；检查年份边界 2000 和 2100。
5. 提交预约，检查用途、时段、冲突提示、替代时段/设备建议，以及“我的预约”中的数据来源说明。
6. 分别以 `student` 和 `admin` 登录，检查预约列表可见范围、管理员演示确认与取消申请处理。
7. 提交设备报修，由管理员接手、暂停预约并解决；检查故障/维护日期对本机预约的阻止效果。
8. 发布公告和维护安排，确认用户页面的公告栏与维护日历同步展示。
9. 加入候补，完成交接检查并记录归还；检查候补提示和归还异常自动生成的问题记录。
10. 在预约时开放协调，在另一演示账号提交符合格式的时段请求并同意；核对本地变更和服务端原始日期提示。
11. 测试服务概览统计、页面导航，以及断开服务端后的缓存只读状态。
12. 不启动课程服务端，在登录页分别点击两个“完整流程演示”入口；检查示例设备、预约日期、服务公告和管理员统计均有数据。
13. 使用者选择微单相机的示例预约日期并尝试相同的 09:00—11:00 时段，检查冲突提示和 11:00—13:00 空档建议；改选建议时段并提交，确认预约显示在预约中心与当日登记。
14. 使用者在开放协调列表向管理员示例预约发起时段请求；退出后进入管理员体验并接受请求，确认协商记录变更。
15. 管理员处理待处理报修并暂停预约；检查维护日期会阻止预约，完成预约归还检查后候补记录出现空档提醒。

课程接口行为、跨域设置和真实服务端预约冲突需要在运行课程提供的 Windows 服务端时另行核验；本机完整演示用于无服务端条件下验证前端交互和业务状态流转。
